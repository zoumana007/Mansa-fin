# 33 — Cadre juridique, CGU, contrats, consentements et documents légaux de Mansa

## 1. Objet du document

Ce document définit l’architecture officielle de gestion juridique et documentaire de Mansa.

Il couvre :

- les Conditions Générales d’Utilisation ;
- les Conditions Générales de Vente ;
- les contrats commerçants ;
- les contrats partenaires ;
- les contrats institutionnels ;
- les mandats ;
- les consentements ;
- les politiques de confidentialité ;
- les politiques relatives aux cookies ;
- les documents d’information ;
- les contrats de cartes ;
- les contrats de paiement ;
- les contrats TPE ;
- les contrats API ;
- les contrats liés aux services publics ;
- les signatures ;
- les versions ;
- les preuves d’acceptation ;
- les traductions ;
- les retraits ;
- les résiliations ;
- les notifications juridiques ;
- les litiges ;
- les obligations multi-pays ;
- l’archivage ;
- l’audit.

L’objectif est de garantir que les engagements juridiques de Mansa soient :

- clairs ;
- accessibles ;
- versionnés ;
- applicables au bon pays ;
- acceptés de manière traçable ;
- conservés ;
- traduits ;
- opposables lorsque nécessaire ;
- révisables ;
- reliés aux fonctionnalités réellement utilisées.

---

# 2. Principes fondamentaux

## 2.1 Aucun texte juridique sans version

Chaque document doit posséder :

- identifiant ;
- type ;
- version ;
- pays ;
- langue ;
- date de publication ;
- date d’entrée en vigueur ;
- statut ;
- auteur ;
- approbateur ;
- historique.

---

## 2.2 Une acceptation doit être prouvable

Mansa doit pouvoir démontrer :

- qui a accepté ;
- quel document ;
- quelle version ;
- à quelle date ;
- depuis quel canal ;
- dans quelle langue ;
- avec quel appareil ;
- dans quel pays ;
- pour quel service ;
- avec quelle méthode de validation.

---

## 2.3 Un document doit correspondre au service réel

Les contrats et conditions ne doivent pas décrire des fonctionnalités inexistantes ou non disponibles dans le pays concerné.

---

## 2.4 Les changements importants nécessitent une nouvelle acceptation

Une nouvelle acceptation peut être nécessaire lorsqu’un changement concerne notamment :

- frais ;
- responsabilités ;
- services ;
- données ;
- résiliation ;
- limites ;
- paiements ;
- partenaires ;
- droits utilisateur ;
- obligations ;
- recours ;
- règlement des litiges.

---

## 2.5 Les textes doivent rester compréhensibles

Les documents juridiques doivent être :

- structurés ;
- lisibles ;
- accessibles ;
- traduits ;
- accompagnés d’un résumé lorsque nécessaire ;
- disponibles avant acceptation.

# 75. Règles métier

1. Tout document possède une version.
2. Toute version possède une date d’effet.
3. Les documents sont liés à un pays.
4. Les documents sont liés à une langue.
5. Toute acceptation est traçable.
6. Une preuve d’acceptation ne peut pas être modifiée.
7. Les contrats signés sont immuables.
8. Les avenants ne remplacent pas silencieusement l’historique.
9. Les modifications importantes peuvent exiger une réacceptation.
10. Les traductions sont versionnées.
11. Les tarifs sont séparés des textes non tarifaires lorsque nécessaire.
12. Les frais sont affichés avant l’opération.
13. Les signatures sont vérifiables.
14. Les représentants sont autorisés.
15. Les mandats sont révocables.
16. Les expirations déclenchent des alertes.
17. Les résiliations suivent un workflow.
18. Les litiges sont rattachés au document concerné.
19. Les documents importants sont archivés avec intégrité.
20. Les accès sensibles sont audités.
21. Les contrats multi-pays restent séparés.
22. Les utilisateurs peuvent consulter les documents acceptés.
23. Les consentements marketing sont distincts.
24. Les cookies non essentiels respectent les choix.
25. Les actions juridiques critiques nécessitent une approbation.

# 78. Critères d’acceptation

Le cadre juridique est validé lorsque :

- les documents sont versionnés ;
- les pays et langues sont gérés ;
- les acceptations sont traçables ;
- les preuves sont immuables ;
- les contrats sont signables ;
- les signatures sont vérifiables ;
- les avenants sont gérés ;
- les consentements sont distincts ;
- les retraits sont possibles ;
- les tarifs sont versionnés ;
- les notifications juridiques fonctionnent ;
- les expirations sont surveillées ;
- les résiliations sont contrôlées ;
- les représentants sont vérifiés ;
- les traductions sont liées à la source ;
- les archives préservent l’intégrité ;
- les actions critiques sont auditées ;
- les tests couvrent les scénarios principaux.
